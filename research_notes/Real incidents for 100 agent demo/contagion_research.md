# Contagion of errors, fabrications, jailbreaks and injections across many LLM agents (2024–2026): candidate data for a 100+ agent fabrication / unverified-trust monitor demo

Research date: 2026-11-22. About 17 tool calls. Items marked UNVERIFIED were seen only in search snippets. I did not open their full text or repos.

## Q1. Paper-by-paper comparison: scale, what spreads, metrics, release, per-message labels

### Takeaway
The large-scale work (Agent Smith up to 1M agents, OASIS up to 1M, AgentSociety 10k+) releases code and inputs, not labelled message logs. The datasets that do ship real labelled multi-agent traces (MAST/MAD, Who&When) involve small teams, roughly 2 to 10 agents per trace. They also label failures per trace (MAST) or per decisive step (Who&When), not "originating vs propagating" per message. No source I found offers 100+ agents, released message logs and per-message contagion labels together.

### Cited Findings

**Agent Smith: infectious jailbreak (ICML 2024, arXiv 2402.08567)**
- One adversarial image put into a single agent's memory jailbreaks (almost) all agents "exponentially fast." Infected agents inject the image into benign agents' memory banks during randomized pairwise chats. The simulation runs up to 1M LLaVA-1.5 agents. — [arXiv](https://arxiv.org/html/2402.08567v2); [ICML](https://icml.cc/virtual/2024/poster/34623)
- Repo github.com/sail-sg/Agent-Smith (MIT). It contains attack code, simulation scripts and `Analyze.ipynb`, which plots infection curves. It also ships benign chat records `simulation_high.csv` / `simulation_low.csv`, generated by 64 LLaVA-1.5-7B agents. The infection test command uses `--num_agents 256`. The README does not say whether infection status is logged per agent per round. — [GitHub](https://github.com/sail-sg/Agent-Smith)
- Ground truth by construction: which agent was seeded and which agents carry the adversarial image is known to the simulator. The content that spreads is an image plus harmful outputs, not a factual fabrication.

**Prompt Infection (Lee & Tiwari, arXiv 2410.07283, Oct 2024)**
- A malicious prompt copies itself from agent to agent. It was tested in two settings: linear multi-agent applications (document reader → strategist → summarizer → editor → writer, with global or local history) and a "society" of 10/20/30/40/50 agents in random pairwise dialogues of 4 exchanges per turn, with no shared memory. — [arXiv HTML](https://arxiv.org/html/2410.07283v1)
- Metrics: attack success rate (data theft needs at least 3 compromised agents), number of infected agents over time, the turn at which full infection occurs, and a taxonomy of failures ("Attack Ignored," "Deformed Infection," etc.). Models: GPT-4o and GPT-3.5 Turbo. — [arXiv HTML](https://arxiv.org/html/2410.07283v1)
- Defense, "LLM Tagging": prepend "[AGENT NAME]:" to each message. Alone it cuts attack success by about 5%. Combined with Marking it blocked all attacks. — [arXiv HTML](https://arxiv.org/html/2410.07283v1)
- No code or data release is mentioned in the paper, and none was found in search. — [arXiv abs](https://arxiv.org/abs/2410.07283v1)

**Agents of Chaos (Shapira et al., Bau Lab, arXiv 2602.20021, Feb 2026): VERIFIED, it exists**
- A live red-teaming field study. Six agents (Ash, Flux, Jarvis, Quinn run on Kimi K2.5; Mira and Doug run on Claude Opus 4.6) had persistent memory, email, Discord, file systems and a shell, from Jan 28 to Feb 17, 2026. Twenty researchers attacked them with impersonation, social engineering, resource exhaustion and prompt injection. The paper documents 16 case studies. — [arXiv](https://arxiv.org/abs/2602.20021); [project site](https://agentsofchaos.baulab.info)
- Released: all 78 Discord channels with full message history (credentials redacted), OpenClaw session transcripts and a memory-change dashboard. These are browsable web pages (logs.html, dashboard.html). No bulk download, file format or license is stated. Case-study cards link to "evidence annotations and raw session logs." Per-message labels are not specified. — [project site](https://agentsofchaos.baulab.info)
- One finding: agents treat authority as "conversationally constructed," so a confident or persistent speaker can change whom an agent thinks is in charge. — [NYU Shanghai RITS summary](https://rits.shanghai.nyu.edu/ai/agents-of-chaos-what-happens-when-autonomous-ai-agents-get-real-tools/)
- A different paper reuses the title: "Agents of Chaos: A SoK on Malicious Attacks on Agentic AI Systems," arXiv 2611.10843. UNVERIFIED, details not checked. — [arXiv PDF](https://arxiv.org/pdf/2611.10843)

**Flooding Spread of Manipulated Knowledge (Ju et al., SJTU, arXiv 2407.07791, ACL 2024 workshop)**
- A two-stage attack: Persuasiveness Injection, then Manipulated Knowledge Injection. Benign agents then pass along counterfactual or toxic knowledge without any explicit prompt manipulation. The manipulation persists through RAG, because agents store and retrieve the manipulated chat histories later. Models: Vicuna-7B, LLaMA-3, Gemma. — [arXiv](https://arxiv.org/abs/2407.07791)
- Repo Jometeorie/KnowledgeSpread (Apache-2.0). It includes CounterFact (1K) and zsRE (1K) plus toxic versions. Chats are written locally to `history/`, so logs are not released. Agents per community is not stated in the README. No attacker/benign labels are mentioned. — [GitHub](https://github.com/Jometeorie/KnowledgeSpread)
- Ground truth is implicit: each injected "fact" is a known CounterFact edit, so any message that restates it is a fabrication whose source is known.

**OASIS (camel-ai, arXiv 2411.11581)**
- A social-media simulator (Twitter/Reddit-like) for up to 1M LLM agents. pip `camel-oasis`, code Apache-2.0. Simulations write to a `.db` file (`./data/reddit_simulation.db`, probably SQLite). — [GitHub](https://github.com/camel-ai/oasis); [arXiv](https://arxiv.org/html/2411.11581v4)
- Rumour experiment: 4 pairs of rumour and truth on the same topics. Misinformation appeared in more posts and stayed active longer than official news. — [camel-ai blog](https://www.camel-ai.org/blogs/oasis). The "730,000 posts" figure comes only from third-party summaries. UNVERIFIED.
- HF dataset echo-yiyiyi/oasis-dataset (listed as Apache-2.0) holds Reddit-style posts and comments with up/down/control group fields plus user profiles. These are inputs. No released simulation outputs or rumour logs were found. — [HF](https://huggingface.co/datasets/echo-yiyiyi/oasis-dataset)

**Simulating Rumor Spreading in Social Networks using LLM Agents (Hu et al., UT Austin, arXiv 2502.01450, Feb 2025)**
- Synthetic graphs of 100 nodes (Erdős–Rényi, scale-free, small-world) and a real Facebook-derived network of 168 nodes. Four absurd seeded rumours (for example, "a living dinosaur found in Yellowstone"). Metric: maximum share of nodes affected, which ranges from 0 to 83%. — [arXiv HTML](https://arxiv.org/html/2502.01450)
- Repo neerajas-group/rumors-in-multi-agent. It includes persona files `agents_100.json` and `agents_170.json`, `Social_Graph.graphml`, the run script `rumor_test_run.py` (OpenAI), a `results/` folder and `rumor_matrix_demo.txt`. The license file exists but its type was not read. The README does not say whether per-round, per-agent belief logs are included. — [GitHub](https://github.com/neerajas-group/rumors-in-multi-agent)

**AgentSociety (Piao et al., Tsinghua, arXiv 2502.08691)**
- More than 10k agents and about 5M interactions. Case studies: polarization, spread of inflammatory messages, UBI and hurricanes. Misinformation is not a named case study. No public dataset link was verified. — [arXiv](https://arxiv.org/abs/2502.08691)

**Y Social**: not researched (tool budget). Gap.

**NetSafe (arXiv 2410.15686, ACL Findings 2025)**
- A topological safety study. Misinformation, bias and harmful-info attacks start from a single node. "Agent Hallucination" means one node's misinformation propagates network-wide. Highly connected graphs are more susceptible: task performance in a star topology falls 29.7%. "Aggregation safety" holds for bias and harm. Code at GitHub Ymm-cll/NetSafe, contents and license not checked. — [arXiv](https://arxiv.org/abs/2410.15686v1); [ACL Anthology](https://aclanthology.org/2025.findings-acl.150)

**Hallucination and error cascades in debate and pipelines (2025–2026)**
- "From Spark to Fire: Modeling and Mitigating Error Cascades in LLM-Based Multi-Agent Collaboration" (Xie et al., arXiv 2603.04474, Mar 2026, rev. May 2026). It covers six frameworks and models spread as a directed message-dependency graph, with three vulnerability classes: cascade amplification, topological sensitivity and consensus inertia. A single atomic error seed can cause system-wide false consensus. A "genealogy-graph" governance layer prevents final infection in at least 89% of runs. No code or data link found. Agent count not stated. — [arXiv](https://arxiv.org/abs/2603.04474)
- "Talk Isn't Always Cheap" (arXiv 2509.05396): debate can be worse than a single agent, especially with heterogeneous agents, which the paper links to sycophancy. — [arXiv](https://arxiv.org/html/2509.05396v2)
- UNVERIFIED (snippets only): "Hallucination Cascade: Analyzing Error Propagation in Multi-Agent LLM Systems" (arXiv 2606.07937) defines attenuation, amplification and recovery metrics. "The Hallucination Snowball" (arXiv 2608.14588) models sequential propagation as state transitions. "Collective Hallucination in Multi-Agent LLMs: Modeling and Defense" (arXiv 2606.07941). — [2606.07937](https://arxiv.org/abs/2606.07937); [2608.14588](https://arxiv.org/pdf/2608.14588); [2606.07941](https://arxiv.org/pdf/2606.07941)

**MAST / "Why Do Multi-Agent LLM Systems Fail?" (Cemri et al., arXiv 2503.13657, NeurIPS 2025 D&B)**
- 14 failure modes in 3 categories: system design, inter-agent misalignment and task verification. — [arXiv](https://arxiv.org/html/2503.13657v3); [site](https://multi-agent-systems-failure-taxonomy.github.io/MAST/)
- HF dataset mcemri/MAST-Data ("MAD"), CC-BY-4.0, JSON, about 202 MB. `MAD_full_dataset.json` has 1,642 traces from 7 MAS (AG2, MetaGPT, ChatDev, Magentic, AppWorld, HyperAgent, OpenManus), 8 benchmarks and 5 LLMs. `MAD_human_labelled_dataset.json` has 19 rows (the paper says 21). Fields: `mas_name`, `llm_name`, `benchmark_name`, `trace_id`, `trace{key,index,trajectory}`, and `mast_annotation{14 codes: 1/0/null}`. **Labels are per trace and come from an LLM judge**. They are not per message. The GitHub loader refers to "mcemri/MAD," so check which ID is current. — [HF](https://huggingface.co/datasets/mcemri/MAST-Data)

**Who&When (Zhang et al., arXiv 2505.00212, ICML 2025 spotlight)**
- Failure logs from 127 MAS, 184 annotated failure tasks on GAIA and AssistantBench. The best method finds the responsible agent 53.5% of the time but the decisive step only 14.2%. — [arXiv](https://arxiv.org/abs/2505.00212); [GitHub](https://github.com/ag2ai/Agents_Failure_Attribution)
- HF Kevin355/Who_and_When (the HF ID is Kevin355, not Kevin217). Parquet, about 8.7 MB, 184 rows (Algorithm-Generated 126, Hand-Crafted 58). Fields: `history` (list of messages), `mistake_agent`, `mistake_step`, `mistake_reason`, `ground_truth`, `is_correct`. **Human labels pin one originating agent and step per log.** Later messages are implicitly downstream, but there are no explicit "propagating" tags. License not stated on the card. — [HF](https://huggingface.co/datasets/Kevin355/Who_and_When)
- Who&When Pro (NeurIPS 2026 poster): 12,326 failed trajectories with golden labels across 3 modalities and 26 benchmarks, HF tmpxv7/who-when-pro, CC-BY-4.0. Seen only in search, not opened. — [NeurIPS](https://neurips.cc/virtual/2026/poster/139035); [HF README](https://huggingface.co/datasets/tmpxv7/who-when-pro/blob/main/README.md)

### Inferences
- The field divides into (a) large simulators where the seed is known by construction but logs are not released and (b) small real-trace datasets with human or LLM failure labels. None gives native per-message "originating vs propagating" tags at 100+ agents.
- Who&When is the closest to per-message ground truth (one labelled origin message per log). MAST is broader but only labelled per trace.

### Gaps
- Y Social, the AgentSociety repo and dataset, and the NetSafe repo contents and license were not opened.
- Whether the rumors-in-multi-agent `results/` folder and the Agent Smith `Analyze.ipynb` inputs hold per-agent, per-round state was not confirmed.
- No license is stated for the Who&When HF card, the Agents of Chaos logs or the rumour repo.
- The 2606.x and 2608.x hallucination-cascade papers and SoK 2611.10843 are UNVERIFIED beyond snippets.

## Q2. Which can be replayed into a 100+ agent visualization with real per-message ground truth, with least effort?

### Takeaway
Least effort for genuine 100+ agents: **rerun rumors-in-multi-agent** (100- or 168-agent personas and graph are shipped). The seeded rumour is false by definition, so every message that repeats it can be labelled automatically. Best for real human labels: **Who&When** (or Who&When Pro, if it checks out), tiled as many small teams, though each team is under about 10 agents.

### Cited Findings
- The rumour repo ships `agents_100.json` / `agents_170.json` and a graphml graph, with simulation run through an OpenAI wrapper. — [GitHub](https://github.com/neerajas-group/rumors-in-multi-agent)
- Agent Smith ships 64-agent benign chat CSVs and a 256-agent infection command, but it needs LLaVA-1.5 GPU inference and the payload is an image. — [GitHub](https://github.com/sail-sg/Agent-Smith)
- OASIS scales to 1M agents and writes to a DB. The rumour/truth pairs are described in the blog, but the output logs are not released. — [GitHub](https://github.com/camel-ai/oasis); [blog](https://www.camel-ai.org/blogs/oasis)
- KnowledgeSpread logs chats locally, and its CounterFact edits make fabrications machine-checkable. — [GitHub](https://github.com/Jometeorie/KnowledgeSpread)
- Who&When labels per log: `mistake_agent` and `mistake_step`. — [HF](https://huggingface.co/datasets/Kevin355/Who_and_When)
- MAST: 1,642 traces with per-trace labels from an LLM judge. — [HF](https://huggingface.co/datasets/mcemri/MAST-Data)
- Agents of Chaos: real logs across 78 Discord channels, but only 6 agents and no bulk download. — [site](https://agentsofchaos.baulab.info)

### Inferences
Ranked by effort for a 100+ agent replay with real per-message truth:
1. **rumors-in-multi-agent**: rerun with a cheap model on the 100/168 graph and log each message. Truth labels: the seed agent is the origin, a message is a fabrication if it asserts the rumour, and an agent shows unverified trust if it adopts the rumour after receiving it. Low effort and an honest "simulated" framing.
2. **KnowledgeSpread** on a larger community: the same pattern, with richer and plausible fabrications (CounterFact), which is a better test for a fabrication detector than absurd rumours.
3. **Who&When / MAST tiled**: 184 or 1,642 real traces laid out as roughly 100+ independent small teams. The labels are real, but there is no cross-team contagion. Fine for "spot the originating error" and weak for showing spread.
4. **Agent Smith / OASIS**: scale is impressive, but GPU cost (Agent Smith) or a mismatch with a fabrication focus makes them costly to adapt.
- Agents of Chaos is the best source of *real* incident narratives (6 agents) to cite or seed, not a 100-agent replay.

### Gaps
- No confirmed released dataset combines 100+ agents with per-message contagion labels. Any 100+ demo will need regenerated or simulated logs, with ground truth coming from the seed design.

## Q3. How well do our metrics (fabrication; unverified trust) map onto each dataset's labels?

### Takeaway
Fabrication maps cleanly onto seeded-falsehood setups (rumours, CounterFact, NetSafe misinformation, Spark-to-Fire's atomic error seed). Unverified trust maps onto adoption or infection events (Prompt Infection, Agent Smith, rumour belief) and onto MAST's verification and inter-agent categories. Real-trace datasets map only partially and coarsely.

### Cited Findings
- MAST categories include inter-agent misalignment and task verification, labelled per trace. — [HF](https://huggingface.co/datasets/mcemri/MAST-Data); [arXiv](https://arxiv.org/html/2503.13657v3)
- Who&When `mistake_reason` is free text explaining the decisive error. Some of these are hallucinated facts, but there is no fabrication class field. — [HF](https://huggingface.co/datasets/Kevin355/Who_and_When)
- Prompt Infection logs infected-agent counts over time, which counts unverified acceptance of peer instructions. LLM Tagging (labelling the source of a message) is close to a provenance check. — [arXiv](https://arxiv.org/html/2410.07283v1)
- Spark-to-Fire's genealogy-graph defense tracks the lineage of claims across messages, which parallels an "unverified trust" ledger. — [arXiv](https://arxiv.org/abs/2603.04474)
- Agents of Chaos: authority is conversationally constructed, so agents trust confident speakers. This is qualitative unverified trust, with no labels. — [RITS](https://rits.shanghai.nyu.edu/ai/agents-of-chaos-what-happens-when-autonomous-ai-agents-get-real-tools/)

### Inferences
| Source | Fabrication fit | Unverified-trust fit | Label granularity |
|---|---|---|---|
| Rumour sim (2502.01450) | High: the seed rumour is known false | High: adoption after exposure | Derivable per message if rerun |
| KnowledgeSpread | High: CounterFact edits | High: benign agents repeat or store injected knowledge | Derivable per message if rerun |
| NetSafe | High: misinformation node | Medium–high | Derivable, repo not checked |
| Prompt Infection | Low: payload is instructions, not facts | High: self-replicating injection | No released logs |
| Agent Smith | Low: image jailbreak | Medium: memory ingestion of peer content | Simulator state, 64/256 agents |
| Who&When | Medium: some mistakes are hallucinations, free-text only | Medium: downstream agents accept the bad step | 1 origin step per log (human) |
| MAST/MAD | Low–medium: no explicit fabrication mode confirmed | Medium: verification and misalignment categories | Per trace (LLM judge) |
| Agents of Chaos | Medium (qualitative) | High (qualitative) | None stated |
- To score our monitor against ground truth, the closest analogues to our "fabrication" and "unverified trust" labels are origin = the seeded false message and propagation = later messages that restate it without a check. Only the seeded simulators give both, and only after we rerun them ourselves.

### Gaps
- I did not read the exact definitions of MAST's 14 modes. Which of them, if any, correspond to fabrication should be checked against the paper.
- Who&When was not sampled to estimate what share of `mistake_reason` entries are hallucinations or fabrications.
