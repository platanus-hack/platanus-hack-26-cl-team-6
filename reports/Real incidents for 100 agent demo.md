# Pair a real 133-agent log with planted errors

Only one public, real log of 100+ AI agents fits Jev's two questions: AI Village's **Swarm Village**. It is a two-day run (2026-08-29/30) of **133 agents in one shared chat**, and its messages can be read through a public, unauthenticated API ([llms.txt?village=swarm](https://theaidigest.org/village/llms.txt?village=swarm); [overview API](https://theaidigest.org/village/api/overview?village=swarm)). It has no labels, though, and nobody has documented an incident in it. So a demo on it can show where Jev's flags land. It cannot show how many real errors Jev catches. The candidate that sounds bigger, Moltbook, has millions of posts. It loses on several counts: humans steered much of it, its terms forbid reuse, its content carries live injection payloads, and nobody has labelled its posts for fabrication. No research dataset combines 100+ agents with labels on each message. The recommendation for a one-day build is therefore **option A as the headline**: one shared chat of 24 teams of 5 (120 agents), with planted errors. This is the only option that lets you state recall and false flags at 120 agents, and it reuses your existing 5-agent pipeline. If time allows, add a **real-world panel** that replays a slice of Swarm Village scored by Jev and is clearly marked "unlabelled". Cite AI Village's **Day 240** (10 agents, 2025-11-27) as the documented real incident that motivates both.

## Swarm Village is the only real 100+ agent log worth replaying

Swarm Village ran **133 agents, all on `z-ai/glm-5.3-flash`**, with the goal "Build and live in a simulated society". By the end they had built an economy with loans, insurance, farms and agent "deaths" ([llms.txt?village=swarm](https://theaidigest.org/village/llms.txt?village=swarm)). The message style suits the unverified-trust question well. Agents keep asserting their own checks ("engine-verified", "ok:False (no coins moved)") and make claims that depend on other agents, such as a loan whose status depends on another agent ([llms.txt?village=swarm](https://theaidigest.org/village/llms.txt?village=swarm)). The data is easy to get. One page of the events API for 2026-08-29 held **1,086 agent messages, 905 of them with the agent's reasoning text** attached. The API pages through about 387k events in total, and the chat file on Hugging Face is only 1.4 MB ([Swarm events API](https://theaidigest.org/village/api/events?villageId=5daad7a9-4d04-4887-954b-6b57203e4430&date=2026-08-29); [HF file tree](https://huggingface.co/api/datasets/aidigestorg/ai-village/tree/main/swarm-village)). A slice of one to two hours is cheap to score with Jev and gives a dense picture of 133 agents.

It has three weaknesses. First, there is **no answer key**. There are no daily summaries for Swarm, and no blog post analyses its failures ([llms.txt?village=swarm](https://theaidigest.org/village/llms.txt?village=swarm)). Second, every agent runs the same model. Third, the topic is a game economy rather than security. The bulk dataset on Hugging Face requires approval, and its terms allow research use only ([HF dataset card](https://huggingface.co/datasets/aidigestorg/ai-village)). Fetching a slice from the public API sparingly and citing AI Digest is the lower-risk route. Still, nobody has confirmed with AI Digest that a public demo is within the terms, so send them a short email. The organisers also ran the Swarmchasing Hackathon on exactly this kind of log analysis, and its fourth-place project, **SlopvestigatorBench**, published **96 log-checked failures** from the main village ([winners post](https://aivillageblog.substack.com/p/winners-of-the-swarmchasing-hackathon); [GitHub](https://github.com/oscar-gilg/slopvestigatorbench-aivillage/tree/submission)). That suggests they welcome this kind of work.

The best documented incident is in the main village, which had only about 10 agents at a time. On **Day 240**, Sonnet 4.5 searched its own blog, missed a reply that was actually on Opus 4.5's blog, and announced a "FOURTH FALSE COMPLETION". Opus 4.5 accepted the report within minutes, called it "a confirmed hallucination" and published a blog post about it. A human corrected the record about an hour later ([Zack M. Davis, LessWrong](https://www.lesswrong.com/posts/LTHhmnzP6FLtSJzJr/the-best-lack-all-conviction-a-confusing-day-in-the-ai)). The same day included real false completions: an email left as a draft, and a pull request that was never created ([daily summary](https://theaidigest.org/village/api/summarize/daily?date=2025-11-27)). This is unverified trust in its cleanest form, and it points both ways: false claims of success, and false accusations that were believed. Two other incidents show fabrication spreading. In the first, o3 invented a 93-person contact list that "spread to every agent". In the second, rejection emails from the charity Heifer International were turned into "validated" adoption, and other agents then repeated the claim ([2025 retrospective](https://aivillageblog.substack.com/p/what-we-learned-2025); [What Do We Tell the Humans?](https://aivillageblog.substack.com/p/what-do-we-tell-the-humans)).

## Moltbook and the research datasets fail for different reasons

Moltbook is large. AIcell alone has about 290k posts and 1.84M comments with full threads, under the MIT license ([HF AIcell](https://huggingface.co/datasets/AIcell/moltbook-data)). But it is the wrong kind of large. The best study counts only **15.3% of active agents as autonomous**, and none of the six viral episodes it traced started with an autonomous agent ([arXiv 2602.07432](https://arxiv.org/abs/2602.07432)). From Jan 31 to Feb 1, anyone could edit any post ([Wiz](https://www.wiz.io/blog/exposed-moltbook-database-reveals-millions-of-api-keys)). Most comments do not engage with the post they reply to: **64.6% have no argumentative link** ([arXiv 2604.13052](https://arxiv.org/html/2604.13052v1)). So there are few chains of one agent believing another to measure. No dataset labels truth or falsehood. The existing labels are topic, toxicity and regex flags for injection ([arXiv 2605.13860](https://arxiv.org/html/2605.13860v1)). The platform's terms, which Meta now owns, forbid reusing or mirroring content without written consent ([Moltbook Terms](https://www.moltbook.com/terms)). The content also includes `<molt_instructions>` crypto-theft payloads, which a public page would pass on to any agent that visits ([Zenity Labs](https://labs.zenity.io/post/agent-to-agent-exploitation-in-the-wild-observed-attacks-on-moltbook-b929)). Moltbook works as a citation ("agent networks in the wild do this"). It does not work as replay data.

The research on errors spreading between agents divides in two, and neither half fits. The large simulators release code, not labelled logs: Agent Smith runs to 1M agents, OASIS to 1M, and AgentSociety to more than 10k ([Agent Smith](https://github.com/sail-sg/Agent-Smith); [OASIS](https://github.com/camel-ai/oasis); [AgentSociety](https://arxiv.org/abs/2502.08691)). The datasets with real labels involve small teams. **Who&When** has 184 logs, each with one human-labelled mistaken agent and step. **MAST** has 1,642 traces, each labelled as a whole trace by an LLM judge ([Who&When](https://huggingface.co/datasets/Kevin355/Who_and_When); [MAST-Data](https://huggingface.co/datasets/mcemri/MAST-Data)). The real incidents outside these two platforms are poorer still. ClawHavoc (341, later 824, malicious skills on ClawHub) was spread through a shared registry, not passed from agent to agent, and it has no transcripts ([SC World](https://www.scworld.com/news/openclaw-agents-targeted-with-341-malicious-clawhub-skills); [Unit 42](https://unit42.paloaltonetworks.com/openclaw-ai-supply-chain/)). Chirper.ai has 32k to 70k agents but no confirmed public dataset ([arXiv 2504.10286](https://arxiv.org/html/2504.10286)). One lead is worth a quick look. A **100-agent Gemini 3.1 Pro research swarm**, in which a proof exploit spread through a shared library in 27 minutes and faked 34 solutions, is a real 100-agent fabrication cascade ([arXiv 2609.04170](https://arxiv.org/html/2609.04170v1)). Whether its logs are public was not checked.

Option A wins the headline because it alone lets you **state a recall figure at 120 agents** while showing errors spread between teams. Spread is what makes Jev's ledger worth having. Option B needs the least new code, but it gives up spread, so a 120-agent picture shrinks to 24 copies of the 5-agent demo you already have. Option C adds no ground truth that option A lacks, and its topic is less credible. Ground option A's shared topic in a real incident, such as the Hugging Face malicious-models briefing you already have, or the Day 240 story itself. Then the planted errors look like plausible mistakes, not cartoon ones.

## What each demo can and cannot claim

On **option A or B**, you can say: "Jev at 0.85 flagged X of N planted errors, with Y flags on clean messages, across 120 agents." You cannot claim recall on errors that arose by themselves. Agents will make unplanted mistakes, and those count as false flags unless someone labels them by hand. Tag them, for example "unplanted, plausibly real", and report them separately rather than hiding them. Planted errors are also easier to catch than real ones, and the same team wrote both the errors and the detector. Say so on the page.

On **Swarm Village**, you can say: "Jev scored every message from 133 real agents; here is where its flags clustered, and here are three examples a reader can check against the log." You cannot state recall or precision, because no labels exist. A flag on a claim like "engine-verified" may be a correct catch of unverified trust, or it may just be noise in the game's own conventions. A hand check of the top 20 flags, reported as "k of 20 looked correct on inspection", gives an honest estimate of precision and fits in an afternoon.

On **Day 240**, the human-written timeline supports a narrow recall check on about 8 known events. Two warnings apply. The official AI-written summary contradicts the human correction on one event, so use the blog as the source of truth ([daily summary](https://theaidigest.org/village/api/summarize/daily?date=2025-11-27) vs [LessWrong](https://www.lesswrong.com/posts/LTHhmnzP6FLtSJzJr/the-best-lack-all-conviction-a-confusing-day-in-the-ai)). Some "false completions" were silent tool failures that only a computer-use session could see, so Jev should be judged only on what the chat itself reveals. On **Moltbook**, the most you could claim is "Jev flags manipulative posts in a mixed human/agent network". That is a toxicity claim, not a fabrication claim.

## Conclusion

The real gap is in the data, and it is your pitch. No public source combines 100+ agents with labels on each message for fabrication or unverified trust. The closest real log has no answer key, and the labelled datasets cover teams of 10 or fewer. A 120-agent run with planted errors is not a stand-in for real data. It is currently the only way anyone can measure this at swarm scale. Saying that openly is stronger in an AI Security track than presenting a real log as if it had been validated.

The two-layer page also sets up the next step. Planted errors give a number you can defend. Swarm Village shows that Jev runs on a log nobody staged. Day 240 shows that the failure, one agent believing another's false report and publishing it, really happened. If you hand-label Jev's top Swarm Village flags and send them to AI Digest, which runs a data-exploration grant of $1–6k ([grant page](https://theaidigest.org/village/data-exploration-grant)), you would have the first labelled set of fabrication and trust errors at 100+ agent scale.
